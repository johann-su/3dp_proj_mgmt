# Features

This section is a feature-by-feature deep dive: not just *what* each feature
does, but *how* it works under the hood and the things worth knowing when you
rely on it — where data lives, what is approximate, what a sync will and won't
touch, and where a feature quietly turns off when its optional service isn't
configured.

Two facts shape almost everything below:

- **The whole catalog is private.** Every page requires sign-in, so a link you
  share only opens for other signed-in users on the instance — but it does open
  *at the page you shared*: sign-in preserves the destination and lands them
  there afterwards. See [access control](/features/models#who-can-do-what).
- **Editing is collaborative; deleting is owner-scoped.** Any signed-in user can
  edit any model or collection (fields, files, variants, syncs). Destructive
  actions — deleting a model or collection, removing a generated variant — stay
  with the owner and with [moderators/admins](/roles).
