# API reference

This page documents the HTTP endpoints Print Vault exposes under `/api`. They
are the same endpoints the browser UI calls — **not a separate, stable public
API**. There is no versioning guarantee and no API-key mechanism: treat them as
internal to the app and expect them to change alongside it.

A few conventions hold across the whole surface:

- **Base URL.** Every path below is relative to your deployment's public origin
  (`BETTER_AUTH_URL`, e.g. `https://models.example.com`) — so
  `POST /api/import` means `POST https://models.example.com/api/import`.
- **Authentication is by session cookie.** Almost every endpoint requires a
  signed-in [session](/roles) and returns `401 {"error":"Unauthorized"}`
  without one — the whole catalog is private. Two credentials work instead of a
  cookie, both for consumers that cannot send one. The **signed file token**
  accepted by the file-serving routes (the image optimizer and slicer deep
  links) is minted by the app, not something a client requests. The
  **[slice-push token](/features/slicing#push-from-slicer)** is the one
  credential you can hand to a program of your own: it is created in Settings →
  Push from slicer, sent as `Authorization: Bearer …`, and works on the three
  slice-push endpoints below — resolving a file to a model, and attaching a
  sliced file to one. There is no general-purpose API key.
- **JSON in and out.** Request and response bodies are JSON unless noted (file
  uploads send raw bytes; downloads and the STL preview return binary; the BOM
  export returns CSV). Errors are `{ "error": "<message>" }` with a matching
  status code.
- **This is not the whole surface.** Most mutations — creating and editing
  models and collections, trash and restore, user roles, connecting Bambu/
  Onshape accounts — run through **Next.js Server Actions**, not REST routes,
  so they don't appear here. This page covers the `/api/*` routes only.

## Authentication

### `GET|POST /api/auth/*`

All authentication is delegated to [Better Auth](https://www.better-auth.com/),
which mounts its own handler under this catch-all: email/password sign-up and
sign-in, sign-out, the session endpoint, and the [OIDC single sign-on](/sso)
authorize/callback when configured. Request and response shapes are Better
Auth's own; the app does not add routes here. Self-registration can be turned
off with `DISABLE_SIGNUP` (see [Configuration](/configuration)).

## File uploads & downloads

### `POST /api/upload`

Stages a single uploaded file into S3 under an unguessable `uploads/…` key and
returns a descriptor. This is the first half of the create/edit flow — the
returned `key` is later committed to a model by a server action. The upload is
**streamed**, so large `.3mf` files never buffer in memory.

- **Query params** — `filename` (required) and `kind` (required, one of
  `model` | `image` | `pdf`).
- **Body** — the raw file bytes.
- The extension must be allowed for the `kind` (e.g. an image `kind` rejects a
  `.3mf`); the served content type is derived from the extension, never the
  request header.

| Status | Meaning |
|---|---|
| `200` | `{ key, filename, size, contentType, kind }` |
| `400` | Missing `filename`/`kind`, a disallowed extension, or an empty body |
| `401` | Not signed in |

### `GET /api/uploads/preview?key=<key>`

Serves a **staged image** (an `uploads/…` object) so the create form can show a
thumbnail of a file imported by URL before the model exists. Restricted to
images with a well-formed staging key — it is deliberately not a general S3
proxy. Returns the image inline, or `404` for a non-image, malformed key, or
missing object.

### `GET /api/files/<id>`

Serves a stored model file, image, or PDF by its file `id` (a UUID). This is the
main download/serve route.

- **Auth** — a **session cookie** *or* a signed file token via `?token=<token>`.
- **Query params** — `token` (optional; the cookie-less credential) and
  `download=1` (optional; forces an attachment download of an otherwise-inline
  image/PDF).
- Model files are always sent as an attachment; images and PDFs stream inline
  unless `download=1`. The content type comes from the file's allowlisted
  extension (never a stored value) and downloads are counted as a metric.

| Status | Meaning |
|---|---|
| `200` | The file bytes, with `Content-Disposition` and `Content-Type` set |
| `401` | No session and no valid token |
| `404` | Bad UUID or unknown file |

### `GET /api/files/<id>/<token>/<filename>`

The same file as `/api/files/<id>`, addressed with the token as a **path
segment** and a trailing filename. This form exists for **slicer deep links**
(OrcaSlicer, Bambu Studio), which download the URL without cookies and derive a
real `.3mf` name from the last path segment — and which don't strip the query
string, so the token can't live in `?token=`. The `id` UUID is authoritative;
the `filename` is cosmetic. See
[Open in slicer](/features/slicing#open-in-slicer).

### `GET /api/files/versions/<versionId>/<index>`

Serves one file of a **version snapshot** (see [Versioning](/features/versioning))
for the version-preview page. Historical files have no stable `id`, so they are
addressed as `(version row, index into that snapshot's file list)` — both
immutable. Auth mirrors `/api/files/<id>` (session cookie or `?token=`);
`download=1` forces an attachment. Snapshot views are **not** counted as
downloads. Returns `404` for a non-positive/out-of-range index or unknown
version.

## Platform import

See [MakerWorld & Printables](/integrations/makerworld-printables) and
[Onshape](/integrations/onshape) for what these importers do; the contracts here
are just the HTTP shapes.

### `POST /api/import`

Imports a **single model** from a MakerWorld, Printables, or Onshape URL. It
resolves and stages the files, then returns a *draft* the create form
pre-fills — nothing is saved to the catalog until the user completes the form.
The route is multi-phase to handle confirmation prompts and Onshape's tab
picker; the client re-POSTs with extra fields as prompted.

**Request body**

| Field | Type | Notes |
|---|---|---|
| `url` | string | Required. A MakerWorld, Printables, or Onshape model URL (tracking query params are stripped). |
| `confirm` | boolean | Set on the re-POST after the user agrees to import a model with many files. |
| `onshapeElements` | string[] | Onshape only: the element (tab) ids picked in the selection dialog. |
| `onshapeWvm` / `onshapeWvmId` | string | Onshape only: a branch (`w`) or version (`v`) and its id, overriding the URL's pin. |

**Responses** — all `200` unless the URL is unusable; the body's shape tells the
client which phase it's in:

- **Draft** (the success case) — `{ source, sourceUrl, title, description, tags,
  categories, files, bom, warnings, onshapeMicroversion }`.
- **Needs confirmation** — `{ needsConfirmation: true, fileCount, title }` when
  the model has a lot of files. Re-POST with `confirm: true`.
- **Needs Onshape selection** — `{ needsOnshapeSelection: true, title, tabs,
  maxTabs, branches, selected }` for a multi-tab or multi-branch document
  (`maxTabs` is the server-side export cap, currently **8**). Re-POST with
  `onshapeElements` (and optionally a branch).

| Status | Meaning |
|---|---|
| `400` | Invalid/unsupported URL, or a MakerWorld *collection* link (use the collection import) |
| `401` | Not signed in |
| `502` | The source platform rejected the request (`ImportError` — message is safe to show) |
| `500` | Unexpected import failure |

### `POST /api/import/archive`

Imports a **`.zip` exported by `GET /api/models/<id>/export`** (this instance or
another one) and returns the same *draft* the create form pre-fills from —
nothing is saved to the catalog. The archive's files are unpacked and staged to
S3; its `metadata.json` supplies the title, description, tags, category name,
BOM (sections included) and per-file provenance. Archives predating that
manifest fall back to the folder names, `README.md` and `bom.csv`.

- **Body** — the raw `.zip` bytes (not multipart), like `POST /api/upload`.
  `?filename=` is optional and only used as the title when the archive names
  the model nowhere.
- **`200`** — a draft: `{ source: "archive", sourceUrl, title, description,
  tags, categories, files, bom, warnings, onshapeMicroversion }`. Files the
  OpenSCAD customizer generated are omitted and reported in `warnings`.
- **`400`** not a readable zip, no archive uploaded, or no model files inside ·
  **`401`** not signed in · **`413`** larger than 250 MB · **`500`** unexpected
  failure.

### `POST /api/import/collection`

Starts a **background import of a whole MakerWorld collection**. It validates the
URL and the user's Bambu connection, creates a local collection plus an
`import_jobs` row, kicks off the runner, and returns immediately — progress is
polled from `GET /api/import-jobs`.

- **Body** — `{ url }` (a MakerWorld collection URL).
- **`200`** — `{ jobId, collectionId, title, total }`.
- **`400`** invalid URL · **`401`** not signed in · **`502`** platform error ·
  **`500`** unexpected failure. A validation failure from the job starter (e.g.
  no Bambu account) comes back as `{ error }` with its own status.

### `GET /api/import-jobs`

Returns the signed-in user's **3 most recent import jobs**, newest first —
polled by the header progress indicator. On each poll it also self-heals:
`running` jobs whose runner has gone silent for over 10 minutes (a server
restart) are marked `failed`.

- **`200`** — `{ jobs: [{ id, status, sourceUrl, collectionId, total,
  completed, failed, skipped, currentItem, error, warnings, createdAt }] }`.
  `status` is one of `running` | `completed` | `failed` | `canceled`.
- **`401`** not signed in.

### `POST /api/import-jobs/<id>/cancel`

Flags a **running** job as `canceled`; its runner notices between designs and
stops. Models imported so far are kept. Only the job's owner can cancel it.

- **`200`** — `{ ok: true }`.
- **`404`** — no *running* job with that id owned by the caller · **`401`** not
  signed in.

## Models

### `GET /api/models/<id>/bom`

Downloads a model's [bill of materials](/features/bill-of-materials) as a **CSV**
file (`Content-Disposition: attachment`, filename derived from the model title).
Reached from a download link on the model page, so it requires the session
cookie. Returns `404` for a bad UUID, an unknown model, or a model with an empty
BOM; `401` when not signed in.

### `GET /api/models/<id>/export`

Downloads everything attached to a model as a single **`.zip`**
(`Content-Disposition: attachment`, named `<model-title>_v<version>.zip` after
the model title and the [version](/features/versioning) being exported):

```
metadata.json  manifest — read back by POST /api/import/archive
README.md      title, version, description (Markdown)
bom.csv        the bill of materials — omitted when the model has none
files/         .3mf / .step / .scad model files
documents/     PDF manuals
images/        gallery images
```

`metadata.json` holds what the folder tree can't: tags, the category *name*,
the BOM with its sections, `sourceUrl`, the
[gallery videos](/features/models#gallery-videos) with their carousel slots, and
one entry per file naming its kind,
its real filename, its sync provenance and whether the customizer generated it.

The export is always the model's **current state** — earlier versions can't be
exported — and requires only a session, like the per-file downloads it bundles.
The version number in the filename (and in `README.md`) is the one the model
page's History panel shows for the current version. Names that collide inside a folder get a `-2`,
`-3` suffix. Returns `404` for a bad UUID, an unknown or trashed model; `413`
when the model's files together exceed the export size limit (250 MB); `401`
when not signed in.

### `POST /api/models/<id>/customize`

Renders a [parametric OpenSCAD](/features/parametric) `.scad` file with the
submitted customizer values and stores the result as a generated `.3mf`
**variant** of that file. Open to any signed-in user (the variant lands on the
owner's model); the generator is recorded so a non-owner can later delete their
own variants. Re-submitting an identical parameter set returns the existing
variant instead of re-rendering.

- **Body** — `{ fileId, values }` where `fileId` is the `.scad` file and
  `values` is a map of customizer parameter → value (coerced against the file's
  parsed schema).

| Status | Meaning |
|---|---|
| `200` | `{ status: "created", fileId, filename }` or `{ status: "exists", fileId, filename }` |
| `400` | Not a `.scad` file of this model, no customizer parameters, or a bad body |
| `401` | Not signed in |
| `404` | Model not found |
| `409` | This source already has the max **20** generated variants — delete one first |
| `422` | The `.scad` references external files, is too large, or OpenSCAD rejected it |
| `502` | The OpenSCAD service failed or is unavailable |

### `DELETE /api/models/<id>/customize`

Deletes **one generated variant** (never the `.scad` source itself). The model
owner (or a [moderator/admin](/roles)) can delete any variant; anyone else only
the variants they generated.

- **Body** — `{ fileId }` (the variant to delete).
- **`200`** `{ status: "deleted" }` · **`400`** not a generated variant of this
  model · **`403`** not allowed · **`404`** model not found · **`401`** not
  signed in.

### `POST /api/models/<id>/customize/preview`

Renders the same `.scad` + `values` as `customize` but streams the result
straight back as **binary STL** (`application/octet-stream`, `no-store`) for the
customize page's 3D preview. Nothing is stored — previews don't count against the
variant cap or leave S3 objects behind. Errors match `customize`
(`400`/`401`/`404`/`422`/`502`).

### `POST /api/models/<id>/onshape-sync`

Re-exports the model's [Onshape](/integrations/onshape) source and replaces the
files that came from Onshape, keeping the pre-sync state as a version. Open to
any signed-in user (uses **their own** Onshape connection). Two-phase: a POST
with no `addElementIds` is the **preview**; when the document has gained tabs the
model doesn't carry, it answers `needs-selection` and the client re-POSTs with
the picked tabs (an empty array declines).

- **Body** — `{ addElementIds? }` (the new tabs to add on the apply POST).

| Status | Body / meaning |
|---|---|
| `200` | `{ status: "up-to-date", message }`, `{ status: "needs-selection", newTabs, microversionChanged, maxAdd }`, or `{ status: "updated", files, warnings }` |
| `400` | Not linked to an Onshape document, or no connected Onshape account |
| `401` | Not signed in |
| `404` | Model not found |
| `502` | Onshape API/export error |
| `500` | Unexpected sync failure |

Version pins (`/v/…`) are immutable and always answer `up-to-date`.

### `POST /api/models/<id>/source-sync`

Syncs a model imported from **MakerWorld or Printables** against the platform's
current file list. Imported files mirror upstream; manual files and all metadata
are left untouched. Two-phase like Onshape sync: POST without `confirm` returns a
**preview** of the plan; POST `{ confirm: true }` downloads the new/changed files
and applies it, keeping the pre-sync state as a version.

- **Body** — `{ confirm? }`.

| Status | Body / meaning |
|---|---|
| `200` | `{ status: "up-to-date", message }`, `{ status: "preview", source, toImport, toReplace, toRemove }`, or `{ status: "updated", imported, updated, removed, warnings }` |
| `400` | Not linked to a MakerWorld/Printables source, or MakerWorld files need a connected Bambu account |
| `401` | Not signed in |
| `404` | Model not found |
| `502` | Every download failed, or a platform error |
| `500` | Unexpected sync failure |

### `POST /api/models/<id>/slice-push`

Attaches a project or sliced file to the model as a new revision — the endpoint
the [OrcaSlicer plugin](/features/slicing#push-from-slicer) calls when it syncs
the open project (normally a `.3mf` that replaces the model's own file, keeping
its name).

**One of the few endpoints that does not take a session cookie for a write.** It
authenticates with a push token (`Authorization: Bearer pvpush_…`) created in
Settings → Push from slicer and revocable there. A token stands for a slicer
install, not a model, so the caller is expected to have resolved the target with
`/api/slice-push/resolve` first.

- **Query params** — `filename` (required; must end in `.3mf` or `.gcode`;
  directories are stripped and unsafe characters replaced), `replaces` (the id
  of the file this revises, so the revision keeps that file's name — honoured
  only within the same artifact family), and `batch`/`batchFinal` (several
  pushes recorded as one version, for a slice that arrives one plate at a
  time).
- **Headers** — `X-Slice-Push-Meta` (optional): a small JSON object describing
  the machine and presets that produced the file (`model`, `nozzleDiameterMm`,
  `bedType`, `filamentTypes`, `filamentColors`, `usesSupport`, `presets`), plus
  `printTimeSeconds` and `filamentGrams`. The machine and preset fields are
  what a `.gcode` cannot carry at all; the two estimates are a fallback for a
  `.3mf` whose own embedded predictions are missing or out of date.
- **Body** — the raw file bytes, streamed. Capped at 256 MB.
- A `.gcode` has its print time and filament weight read out of it as it
  streams; a `.3mf` is queued for the normal estimate pipeline instead, which
  reads the per-plate predictions embedded in it. A push that names the file it
  revises (`replaces=<fileId>`), or whose filename matches one already on the
  model, **replaces** that file as a new version and keeps its name; otherwise
  it is appended.

| Status | Body / meaning |
|---|---|
| `200` | `{ status: "replaced" \| "added", filename, printTimeSeconds, filamentGrams }` |
| `400` | Missing/invalid `filename`, or an empty body |
| `401` | Missing, malformed or revoked token |
| `404` | Model not found or trashed |
| `413` | Larger than the 256 MB cap |
| `502` | The upload to object storage failed |

### `POST /api/slice-push/resolve`

Answers "which model is this file on my disk?", so the plugin needs no
per-model setup. Same push-token auth as above.

- **Body** — `{ hashes?: string[], filenames?: string[], designId?: string }`.
  `hashes` are lowercase hex SHA-256 of the files the slicer project was loaded
  from; anything malformed is ignored rather than rejected. Up to 32 of each.
- **Response** — `{ candidates: [{ modelId, modelTitle, fileId, filename, via,
  url, pushUrl }] }`, best first. `via` is `"hash"` (the stored bytes match
  exactly), `"filename"`, or `"source"` (the model was imported from the design
  the 3MF names). Trashed models are never candidates.

| Status | Body / meaning |
|---|---|
| `200` | `{ candidates: [...] }` — an empty array means no match |
| `400` | Body was not JSON |
| `401` | Missing, malformed or revoked token |

### `GET /api/slice-push/ping`

Verifies a URL and token pair at setup time. Returns
`{ ok: true, origin, user }`, or `401`.

## Collections

### `POST /api/collections/<id>/sync`

Re-runs a [collection](/features/collections) import against its stored MakerWorld
source URL. Designs added remotely since the last run import as new models;
everything already in the library is just re-linked into the collection. **Nothing
is deleted** — models removed from the remote collection stay local. Open to any
signed-in user (uses their own Bambu connection); like the collection import it
runs in the background and returns a job to poll.

- **`200`** — `{ jobId, total }`.
- **`400`** the collection wasn't imported from MakerWorld · **`404`** collection
  not found · **`401`** not signed in · **`502`**/**`500`** platform/unexpected
  error.

## Onshape OAuth

These two routes implement the "Sign in with Onshape" flow (see
[Onshape integration](/integrations/onshape)). They are browser redirects, not
JSON endpoints, and are inert unless `ONSHAPE_CLIENT_ID`/`ONSHAPE_CLIENT_SECRET`
are configured.

### `GET /api/onshape/authorize`

Starts the flow: stores a CSRF `state` in a short-lived cookie and redirects the
signed-in user to Onshape's consent screen. Redirects to `/sign-in` when not
signed in, or to `/settings/onshape?error=not-configured` when OAuth isn't set
up.

### `GET /api/onshape/callback`

Onshape's registered redirect target. Verifies the `state` cookie, exchanges the
`code` for tokens, and stores them **encrypted** for the signed-in user, then
redirects to `/settings/onshape`. On failure it redirects there with an `?error=`
code (`denied`, `state-mismatch`, `connect-failed`, `not-configured`).

## MCP server

All of the following are **404 unless `ENABLE_MCP=true`** (see the
[MCP integration](/integrations/mcp)). This is the one part of the API meant to
be called by something other than the app's own UI, and the only one that
accepts a credential other than a session cookie.

### `POST /api/mcp`

The Model Context Protocol endpoint: JSON-RPC 2.0 over HTTP with a single JSON
response (no event stream), exposing read-only catalog tools —
`search_models`, `get_model`, `get_model_bom`, `get_model_print_files`,
`get_model_documents`, `read_document`, `get_document_images`.

- **Authentication** — `Authorization: Bearer <token>`, issued by the OAuth
  flow below. A session cookie is *not* accepted here. Without a valid token
  the response is **`401`** with a `WWW-Authenticate` header naming the
  metadata document to start discovery from.
- A token carries the same read access as the user who approved it: the whole
  catalog, no mutations.
- **`GET`**/**`DELETE`** return **`405`** — the server never pushes messages,
  so there is no stream to open and no session to end.

### `GET /.well-known/oauth-authorization-server`, `GET /.well-known/oauth-protected-resource`

Public OAuth discovery documents (RFC 8414 / RFC 9728) an MCP client reads
before it has any credential. The protected-resource document is also served
under `/.well-known/oauth-protected-resource/api/mcp` and by Better Auth under
`/api/auth/`; all copies are identical.

### `GET|POST /api/auth/mcp/*`

Better Auth's OAuth provider endpoints: `register` (RFC 7591 dynamic client
registration, **unauthenticated** — this is how a client bootstraps),
`authorize`, `token`, `userinfo`, `jwks`. The browser-facing approval screen is
the page at `/mcp/authorize`, which is what the discovery document advertises
as the authorization endpoint.
